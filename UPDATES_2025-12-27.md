## 🐛 Bug Fixes

### 1. History Endpoint Error (CRITICAL FIX)

**Issue:** `/api/v1/history` endpoint returning 500 Internal Server Error

**Error Message:**
```
History error: too many values to unpack (expected 4, got 6)
```

**Root Cause:**
The `get_services()` function returns 6 values:
```python
return _supabase, _embedding, _search, _perplexity, _cache, _budget
```

But several endpoints were only unpacking 4 values:
```python
supabase, _, _, _ = get_services()  # ❌ WRONG
```

**Files Modified:** `app/api/routes/semantic.py`

**Lines Fixed:**
- Line 76: `_, _, search, _, _, _ = get_services()`  (was: `_, _, search, _ = get_services()`)
- Line 260: `supabase, _, _, _, _, _ = get_services()`  (was: `supabase, _, _, _ = get_services()`)
- Line 337: `supabase, embedding, _, perplexity, _, _ = get_services()`  (was: `supabase, embedding, _, perplexity = get_services()`)

**Testing:**
```bash
curl http://localhost:8000/api/v1/history?limit=5
# ✅ Returns: {"session_id":"default","messages":[],"count":0}
```

**Impact:**
- History page now loads without errors
- Users can view conversation history
- No more 500 errors on this endpoint
