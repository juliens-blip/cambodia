┌────────────────────────────────────────────────────────────────────────────┐
│  SOLUTION: Natural Key + Upsert                                            │
└────────────────────────────────────────────────────────────────────────────┘

    Natural Key = commodity_id + date + source + destination_country

    ┌─────────────┬────────────┬────────┬─────────────┬──────────────┐
    │ commodity   │    date    │ source │ destination │   Result     │
    ├─────────────┼────────────┼────────┼─────────────┼──────────────┤
    │ cashew      │ 2024-01-01 │  MEF   │   NULL      │ Record #1 ✅ │
    │ cashew      │ 2024-01-01 │  WITS  │   World     │ Record #2 ✅ │
    │ cashew      │ 2024-01-01 │  WITS  │   USA       │ Record #3 ✅ │
    │ cashew      │ 2024-01-01 │  MEF   │   NULL      │ UPSERT #1 🔄 │
    └─────────────┴────────────┴────────┴─────────────┴──────────────┘

    Records 1-3: Different natural keys → All stored
    Row 4: Same natural key as #1 → Updates #1 instead of creating duplicate

┌────────────────────────────────────────────────────────────────────────────┐
│  DATABASE SCHEMA: Partial Unique Indexes                                   │
└────────────────────────────────────────────────────────────────────────────┘

    Index #1: FOR records WITH destination_country
    ┌──────────────────────────────────────────────────────────────────┐
    │ CREATE UNIQUE INDEX idx_prices_unique_with_destination           │
    │ ON prices(commodity_id, date, source, destination_country)       │
    │ WHERE destination_country IS NOT NULL;                           │
    └──────────────────────────────────────────────────────────────────┘

    Index #2: FOR records WITHOUT destination_country (NULL)
    ┌──────────────────────────────────────────────────────────────────┐
    │ CREATE UNIQUE INDEX idx_prices_unique_without_destination        │
    │ ON prices(commodity_id, date, source)                            │
    │ WHERE destination_country IS NULL;                               │
    └──────────────────────────────────────────────────────────────────┘

    Why two indexes?
    → PostgreSQL treats NULL as distinct in unique constraints
    → Partial indexes handle NULL and non-NULL separately
    → Ensures correct duplicate detection in all cases

┌────────────────────────────────────────────────────────────────────────────┐
│  CODE CHANGES: insert → upsert                                             │
└────────────────────────────────────────────────────────────────────────────┘

    BEFORE (app/scheduler/jobs.py):
    ┌──────────────────────────────────────────────────────────────────┐
    │ # Store in Supabase                                              │
    │ await supabase.insert_price(price_data)                          │
    └──────────────────────────────────────────────────────────────────┘

    AFTER (app/scheduler/jobs.py):
    ┌──────────────────────────────────────────────────────────────────┐
    │ # Store in Supabase using upsert to avoid duplicates            │
    │ await supabase.upsert_price(price_data)                          │
    └──────────────────────────────────────────────────────────────────┘

    NEW METHOD (app/services/supabase_service.py):
    ┌──────────────────────────────────────────────────────────────────┐
    │ async def upsert_price(self, price_data: Dict) -> Dict:         │
    │     result = self.client.table("prices").upsert(                │
    │         price_data,                                              │
    │         ignore_duplicates=False                                  │
    │     ).execute()                                                  │
    │     return result.data[0] if result.data else None               │
    └──────────────────────────────────────────────────────────────────┘
